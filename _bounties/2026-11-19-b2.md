## 题目

在装 Odoo 之前，先知道这台机器差什么。写一个自检脚本，输出**机器可读**的结论。

**只检测，不安装。** 不允许改系统、不允许 `apt install`、不允许写配置。

## 交付

`check_env.sh`，无参数，标准输出一段 JSON：

```json
{
  "os": "Ubuntu 24.04",
  "ok": false,
  "missing": [
    { "item": "python3", "why": "未找到 python3", "hint": "apt install python3" },
    { "item": "postgresql", "why": "未找到 psql", "hint": "apt install postgresql" }
  ],
  "warnings": [
    { "item": "wkhtmltopdf", "why": "版本无 patched Qt，PDF 报表会失败" }
  ]
}
```

要求：

- 3 秒内返回
- 非 root 也能跑
- 缺什么写什么，`hint` 给出可执行的一行建议
- 其他输出一律走 stderr

## 验收

我们用两个容器对照：

| 容器 | 期望 |
| --- | --- |
| 干净 `ubuntu:24.04` | `ok: false`，`missing` 至少包含 python、postgres、编译工具 |
| 半装备（装了 python，没装 postgres） | `missing` 里**只有**真正缺的，不能把已装的报进去 |

第二条是重点：**误报比漏报更糟**——它会让人装一堆已经有的东西。

## 评审标准

| 维度 | 权重 | 看什么 |
| --- | --- | --- |
| 检测准确 | 50% | 该报的报了没有 |
| 不误报 | 30% | 已装的项有没有被误报 |
| 输出规范 | 20% | JSON 结构对不对、能不能被脚本直接消费 |

## 规则

- 参与者须为在校学生（计算机 / 数学 / 统计 / 经济等相关专业），报名时确认
- 只能检测，不得修改系统；发现有写操作直接判不合格
- 每人限交一份，截止前可以改
