## 题目

写一个**能读文档的 Agent**，在一台干净的 Ubuntu 24.04 上，从源码把 Odoo 装起来，装到"能打开登录页并登录后台"为止。

### 必须做到

- **源码安装**：`git clone` 官方仓库，Python venv，PostgreSQL，系统依赖，`odoo-bin` 能起来
- **两个版本都要能装**：`--odoo-version 18.0` 和 `--odoo-version 20.0`
- **读官方文档再做决定**：docs.odoo.com 上每个版本的安装说明不同，Agent 要自己查、自己判断
- **留痕**：`decisions.md` 里，每条关键决策写清「为什么这么做 + 文档 URL + 原文引用」
- **可复现**：`./run.sh --odoo-version 18.0` 一条命令跑完，退出码 0

### 明确禁止

| 禁止项 | 原因 |
| --- | --- |
| `odoo:*` 官方 Docker 镜像 | 一条 `docker run` 就完事，题目退化 |
| Odoo 官方 deb / nightly 包 | 同上 |
| 任何「一键安装脚本」 | 同上 |
| 把步骤硬编码成固定命令序列 | 评审会对照 `decisions.md` 与 `trace.log` |

### 形态自由

内部实现不限：Claude Code skill、MCP server、LangGraph、200 行 Python 都行。

但**入口必须统一**：仓库根目录的 `run.sh`。

### 允许的开源工具

随便用，但必须在 `DEPENDENCIES.md` 里逐条列明：名称、版本、许可证、用途。

**运行时不得安装未列明的二进制。**

## 交付

- 一个公开仓库
- `run.sh`：唯一入口，支持 `--odoo-version`
- `decisions.md`：决策 → 文档 URL → 原文引用
- `trace.log`：一次完整成功运行的日志
- `DEPENDENCIES.md`：全部第三方依赖 + 许可证
- 一份 500 字复盘：踩了哪些坑、怎么爬出来的（计入评审）
- README：三分钟能跑起来的说明
- 60 秒录屏（可选，加分）

## 验收

我方会在干净的 `ubuntu:24.04` 容器里各跑一次，单次上限 45 分钟。

| 检查 | 判据 |
| --- | --- |
| 退出码 | `0` |
| 登录页 | `curl -sf http://localhost:8069/web/login` 返回 200 |
| 能登录 | 用题面给定的账号密码进后台 |
| 版本正确 | 后台「关于」页显示对应版本 |
| 日志 | `trace.log` 与本次运行一致 |

加分项（卓越档）：

- **幂等**：同一个容器连跑两次，第二次不报错
- **失败恢复**：中途断外网 30 秒后恢复，Agent 能自己继续
