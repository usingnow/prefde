指南

如何交作品

一步一步，全程在浏览器里完成 · 不用装 git，也不用记命令

你交的不是代码，是一份「作品说明 + 链接」。代码放在你自己的公开仓库里；投稿只是在我们的仓库里新建一个 md 文件，提一个 Pull Request（简称 PR）。

先记住三件事
  • 投稿 = 提 PR。不是发邮件，不是传网盘，不是交压缩包。
  • 文件路径固定：_submissions/期号/你的GitHub用户名.md
  • 正文只放链接和说明。图片、视频、压缩包一律给外链。

开始之前，确认你有

东西说明
GitHub 账号免费注册，五分钟。它是你唯一的身份，报名和投稿都用它。
一个公开仓库放你的代码和一份能跑起来的 README。仓库必须是 public。
本期期号形如 2026-11-19-b1，在悬赏页标题下方。
演示地址（可选）GitHub Pages、Vercel、一段录屏都行。没有就写「无」。

总览：五步

  1. 把作品放进你自己的公开仓库
  2. 打开本站仓库，fork 一份到你的账号下
  3. 新建 _submissions/期号/用户名.md
  4. 提交，开一个 Pull Request
  5. 等评审，按意见修改

下面每一步都有截图位。图还没补上时，虚线框里写的是「这张图应该拍什么」。

第一步 · 把作品放进你自己的公开仓库

本站仓库不收代码。你的代码、数据、脚本，全部放在你自己的 GitHub 仓库里。仓库里至少要有三样东西：

  • 能跑的代码（或数据、文档，按题目要求）
  • 一份 README：三分钟能让人跑起来
  • 一句说明：你做了什么、怎么验证

仓库要是 public。评审打不开的仓库，等于没交。

第二步 · fork 本站仓库

打开本站仓库：

{{ site.repo_url }}

点右上角的 Fork，再点 Create fork。等几秒，你就有了自己的一份副本，地址是：

https://github.com/你的用户名/{{ site.repo | split: "/" | last }}

后面的新建文件、提交，都在你自己的这份副本里做。PR 会自动指回本站仓库。

第三步 · 新建投稿文件

在你的副本里，点进 _submissions 目录，然后点右上角的 Add file → Create new file。

文件名框里输入（斜杠会自动建目录）：

2026-11-19-b1/你的GitHub用户名.md

把 2026-11-19-b1 换成你那一期的期号，把「你的GitHub用户名」换成你的真实用户名。例如：

2026-11-19-b1/linxiao.md

三个硬规则，错一个都可能不算投稿：

规则为什么
目录名 = 期号，一字不差管理员按目录找投稿，写错就找不到
文件名 = 你的 GitHub 用户名唯一的分身识别方式，天然去重
扩展名是 .mdMarkdown，纯文本，能直接看 diff

第四步 · 写投稿内容

更省事的做法：回到你那一期的悬赏页，点 下载模板。下载下来的 md 已经填好期号、题目、奖励、截止时间、评审标准和本期交付清单，你只需要补自己的仓库链接和说明。

也可以直接复制下面的模板，粘进编辑区，换成你自己的内容。它是「说明书」，不是代码本体。

# 2026-11-19-b1 投稿 · linxiao

- 期号：2026-11-19-b1
- 作品仓库：https://github.com/linxiao/odoo-install-diff
- 演示地址：https://linxiao.github.io/odoo-install-diff/
- 一句话说明：覆盖 8 个主题、24 条差异，每条都附官方文档引用。

## 我做了什么

用脚本抓取 Odoo 18 / 20 两份安装文档，人工核对后整理成 diff.json，
再生成一份可读的 diff.md。

## 怎么跑起来 / 怎么验证

    git clone https://github.com/linxiao/odoo-install-diff
    cd odoo-install-diff
    python3 -m json.tool diff.json
    python3 check_quotes.py

## 复盘

- 两版文档的目录结构不一样，18 的安装页拆得更细，20 合并了。
- 踩坑：中英文文档混用，引用时容易串，最后统一用英文页。

## 自查

- [x] 文件名 = 我的 GitHub 用户名
- [x] 没有提交二进制文件
- [x] 作品为本人原创

不要做的事：

不要为什么
把 zip、图片、视频放进 PR仓库有 1 GB 上限，二进制也没法看 diff
只写「代码在网盘」评审打不开，等于没交
提交 main.py 这类代码文件代码应该在你自己的仓库，这里只放说明
文件名写成 submission.md无法去重，也无法确认是谁交的

第五步 · 提交并开 Pull Request

页面往下拉，点绿色的 Commit changes。在弹出的框里：

  1. 提交说明随便写，比如 投稿 2026-11-19-b1
  2. 选 Create a new branch for this commit and start a pull request
  3. 分支名保持默认，或写 submission/2026-11-19-b1
  4. 点 Propose changes

接下来是开 PR 的页面。确认两件事：

字段应该是什么
base repository{{ site.repo }}，分支 {{ site.branch }}
head repository你的用户名/{{ site.repo | split: "/" | last }}，分支是你刚建的那条

标题建议写成：

[投稿] 2026-11-19-b1 · linxiao

正文里仓库自带的模板会自动出现，把四个字段填上，勾选自查，然后点 Create pull request。

第六步 · 等评审，按意见改

PR 创建后，你会看到三样东西：

  • Conversation：评审在这里留言，你有回复会收到 GitHub 邮件
  • Files changed：只显示你新增的那个 md，代码不在里面，这是正常的
  • Labels：管理员会打上「投稿」标签，方便统一查看

截止前想改，不要新开 PR。在你的分支上再提交一次，PR 会自动更新。网页上的做法是：

  1. 打开 PR，点 Files changed
  2. 点文件右上角的铅笔图标
  3. 改完，提交到同一条分支

截止后，状态会变成「评审中」，不再接受新的投稿。评审意见仍然可以在 PR 里回复。

用命令行提交（可选）

如果你已经会用 git，可以跳过网页步骤：

# 1. 先在网页上 fork 本站仓库
# 2. clone 你自己的副本
git clone https://github.com/你的用户名/{{ site.repo | split: "/" | last }}.git
cd {{ site.repo | split: "/" | last }}

# 3. 开分支
git checkout -b submission/2026-11-19-b1

# 4. 新建文件
mkdir -p _submissions/2026-11-19-b1
$EDITOR _submissions/2026-11-19-b1/你的用户名.md

# 5. 提交并推送
git add _submissions/2026-11-19-b1/你的用户名.md
git commit -m "投稿 2026-11-19-b1"
git push -u origin submission/2026-11-19-b1

push 完，终端会给一个 Compare & pull request 链接，点进去创建 PR。

常见错误

现象原因怎么改
管理员说没收到期号目录写错，或 PR 提错了仓库对照路径，确认 base 是 {{ site.repo }}:{{ site.branch }}
「查看投稿」列表是空的PR 还没被打上「投稿」标签等管理员补打，或在 PR 里 @ 管理员
PR 里看不到代码设计如此，代码在你的仓库在正文里放仓库链接
文件被要求改提交了二进制，或只写了网盘链接改成外链，重新提交
评审说打不开你的仓库是 private改成 public，或给评审加访问权限
截止后被拒提交时间晚于截止时间无法补救，下次赶早

提交前自查

  • 路径是 _submissions/期号/你的GitHub用户名.md
  • 文件名和你的 GitHub 用户名完全一致（大小写也要对）
  • 正文里有作品仓库链接，且点得开
  • 仓库是 public
  • 没有提交 zip、图片、视频
  • PR 的 base 是本站仓库，不是你的副本
